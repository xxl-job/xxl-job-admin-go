# 执行器管理

执行器（Executor）是任务的执行载体。一个执行器分组对应一个 `app_name`，可挂载多台机器（自动注册或手动录入）。

## 执行器分组

进入「执行器管理」可见所有分组列表。

| 字段 | 说明 |
|---|---|
| app_name | 执行器唯一标识，任务通过它路由 |
| 标题 | 展示名 |
| 地址类型 | 0=自动注册 / 1=手动录入 |
| 在线机器 | 当前在线的地址列表 |

## 新建分组

1. 「新建」→ 填写 `app_name`、标题
2. 地址类型：
   - **自动注册**：执行器启动后通过 gRPC 上报地址，无需手动填
   - **手动录入**：填写机器地址列表（逗号分隔），适用于无 gRPC 上报的场景

::: tip
`app_name` 创建后不可修改，它同时是 [用户权限](./user#执行器权限) 的授予单位。
:::

## 在线机器

自动注册的执行器持续上报心跳。掉线的机器会从「在线机器」移除；调度时路由策略只考虑在线机器。

## 执行器开发

如何用 Go 或其他语言编写执行器并连接调度中心，参考执行器 SDK（`pkg/executor`）与下方内置 handler。

## 内置 handler（executor 镜像）

`xxljob/xxl-job-executor` 镜像内置 4 个通用 handler，admin 建 BEAN 任务填名 + JSON 参数即用：httpCall、shellExec、mysqlQuery、sendWebhook。详见 [镜像部署](./docker-images#内置-handler)。
